Three worked AI cost examples

By Ahmadreza Samadi · Start with the decision.

All examples are fictional and AI-assisted. These are arithmetic teaching cases, not company measurements, customer results or a model recommendation. Educational, not financial advice.

Use the original offline CLI included in this package. Python3.10 or newer; no packages, account, API key or network access required. Open a terminal in this folder and run:

python3 -B verify_examples.py

Use python instead of python3 where appropriate. Verification reads the supplied fixtures and reports to the terminal. The original CLI code is unchanged.

Failed attempts still belong in the numerator

Four attempts cost 1.60 USD across three intended results. Only A and C are accepted. Include A’s failed first attempt and B’s rejected output: 1.60 / 2 = 0.80 USD per accepted result. Accepted share is two out of three intended results; it is not three out of four attempts.

No accepted results means undefined unit cost

Two unsuccessful attempts still cost 1.00 USD. The denominator is zero, so the tool returns null for unit cost and its exact fraction. Null does not mean the experiment was free.

Explicitly known zero costs can produce zero unit cost

One accepted result and one failed attempt have explicitly recorded zero in every cost category. Total cost and unit cost are zero. This fictional case assumes all included costs are known to be zero; a free model call alone does not establish zero review, tool or other cost. A missing cost must not be replaced with zero.

Use with your own records

Define one task, period, intended-result population, acceptance rule and currency label before collecting attempts. Keep rejected and failed attempts. Record every included cost category explicitly; price review effort using your own stated time/rate basis. Acceptance is your label, not independent certification. The tool cannot establish whether your records are complete or whether a workflow is better.

These three different fixtures are not a controlled comparison between models or workflows. Do not interpret their different unit costs as productivity or ROI evidence. Pending decisions need a documented cutoff; arbitrary exclusion can bias results.

Use copies for private records. Do not upload sensitive ledgers to a public repository.
